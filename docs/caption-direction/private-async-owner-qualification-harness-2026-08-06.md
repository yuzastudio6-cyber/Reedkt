# Private Asynchronous Caption Owner Qualification Harness — 2026-08-06

Milestone: `POST-CAP-20 private asynchronous owner qualification harness`

Status: `source_complete_ready_for_real_owner_service_binding`

## Outcome

The standalone Caption qualification harness can now await asynchronous
canonical owner services. A bounded internal run may receive the exact Caption
`SkillSupportRequest`, independently execute or reread the selected owner,
inject only that request's private byte-free artifact, and resume Caption until
the job completes or reaches the next owner.

The focused scene proves the required order
`visual_intelligence -> track_all` and reaches `completed` only after both
authenticated owner records are supplied. The historical synchronous fixture
path remains available for contract regressions. The new asynchronous path
does not silently manufacture its missing artifacts.

This is the goal-required test-only coordinator. It is not imported by a
production route and is not the future Orchestra.

## Visible defects

The prior harness could only inject synchronously created fixtures. It could
not await a real asynchronous owner service, which meant the internal
qualification runner did not yet match the goal's independently-executed
support-system requirement.

## Repairs made

- added a separately versioned asynchronous harness entry point;
- made an explicit owner resolver mandatory;
- prohibited implicit fixture artifact creation in the async path;
- required exact artifact count, order, type, producer, privacy, byte-free, and
  selected support-request lineage before resume; and
- preserved the 32-step maximum and HQ-mediated/no-direct-peer rule.

## Known limitations

This milestone proves the executable asynchronous seam, not live owner
qualification. The focused owner records remain closed source fixtures and are
not accepted as Gemini, SAM 3.1, complete-time visual review, independent final
QA, or terminal Caption evidence.
