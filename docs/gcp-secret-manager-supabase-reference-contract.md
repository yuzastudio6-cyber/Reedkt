# GCP Secret Manager Supabase Reference Contract

Prompt 25A defines how ReeditPro refers to Supabase environment values that are expected to live in Google Cloud Secret Manager. It does not fetch, inspect, print, validate, or store any secret value.

## Contract

All staging and production Supabase values must be handled as Secret Manager references, not copied values.

Allowed reference names use the `GCP_SECRET_REF_` prefix and identify the environment and purpose, for example `<GCP_SECRET_REF_SUPABASE_STAGING_DB_URL>`. Reference names are not secrets by themselves, but they still must not be used to imply that access has been verified.

Future URI-style references may use placeholder-only forms such as `gcp-secret://projects/<GCP_PROJECT_PLACEHOLDER>/secrets/<GCP_SECRET_NAME_PLACEHOLDER>/versions/latest`. Real project IDs, real secret names, real versions, and secret payloads are not allowed in repo docs until a future evidence-review prompt explicitly accepts redacted metadata.

## No Raw Supabase Values

Raw Supabase values must not be pasted into:

- chat messages;
- docs;
- scripts;
- SQL files;
- fixtures;
- frontend code;
- PR bodies or comments;
- logs;
- screenshots without redaction;
- CI output.

This includes database URLs, passwords, service-role keys, anon keys, JWT secrets, storage signed URLs, project refs, provider keys, Stripe keys, and any value that could authenticate or identify a real staging or production target.

## Environment Separation

Local validation may use local-only Supabase values generated by local tooling and recorded only as sanitized localhost evidence. Staging and production values must be referenced by Secret Manager reference placeholders only.

Staging references must never be reused for production. Production references must never be used in staging dry-run packets. Any future command packet must prove the target environment from redacted evidence before execution.

## Access And Approval

Access to Secret Manager values is future-only and must require:

- a human approval completion record;
- accepted redacted Supabase project evidence;
- a named execution owner;
- a named service account or approved human operator;
- least-privilege IAM review;
- audit log review;
- rollback and cleanup owner review;
- explicit command packet approval.

Prompt 25A grants none of those approvals.

## Rotation And Revocation

Every future Supabase Secret Manager reference must have a rotation owner, rotation cadence, emergency revoke path, and audit evidence path before staging or production execution.

Rotation status in Prompt 25A is `reference_required` and `access_not_verified`.

## Relationship To Prompt 25

Prompt 25 command templates remain blocked. Prompt 25A only changes the placeholder policy so future command packets point to Secret Manager reference placeholders instead of raw Supabase values.

The next safe Supabase actions remain Prompt 23A for human approval completion and Prompt 24B for redacted evidence review. Prompt 26 can be considered only after approval and accepted evidence exist.
