# Living Frame Active Baseline Route Binding

## Purpose

`living-frame-active-baseline-route-binding-v1` separates two different
claims that must never be confused:

1. the owner-approved twelve-case non-character Living Frame baseline can be
   prepared for internal execution; and
2. advanced temporal A-Roll occlusion still requires released SAM2 runtime,
   artifact, QA, and private-review evidence.

The binding is byte-free and non-executable. It does not create work, select a
provider, dispatch a worker, create an asset, approve QA, or replace the
canonical planner.

## Baseline route

Ten cases keep their primary selected-scene route. Two cases use an approved
scene fallback while the advanced temporal-mask runtime remains unreleased:

- `living_a_roll_compositing_case` uses `safe_space_overlay` after full
  temporal composition and simplified depth are proven unavailable for the
  selected source; and
- `camera_depth_occlusion_and_masks_case` uses
  `simplified_depth_composition`, which may use only an already approved
  static/known-cutout or low-risk depth treatment.

The selected fallback must be the first eligible safe step in the exact
approved scene fallback ladder. Earlier steps require explicit ineligibility
reasons. Later steps are not evaluated once a safe route is selected.

## Professional constraints

- A fallback never counts as proof that advanced temporal masking works.
- The advanced SAM2 route remains open for both affected cases.
- AI video may never solve a mask failure.
- A fallback that changes meaning, cost, scope, or source truth still requires
  the existing user-review or new-approval path.
- Caption, MasterTiming, StoryTiming, SoundSync, work-graph, asset-manifest,
  Remotion, QA, and private-review ownership do not move.
- Static illustration may remain visible, but character animation and all
  living/mechanical rigging remain paused under the owner scope amendment.

## Canonical integration

The canonical planner must reread the exact selected scene, approved snapshot,
fallback ladder, and primary failure evidence before it may admit either
route. This feature-side binding only proves that a deterministic baseline
candidate can preserve professional fallback behavior without falsely closing
the advanced mask gate.

Run the focused source regression after the shared runtime owner releases any
active media window:

```text
npm run smoke:living-frame-active-baseline-route-binding
```
