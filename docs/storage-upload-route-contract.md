# Storage Upload Route Contract

Prompt 4 route contracts define storage/upload boundaries only. They do not enable media analysis, edit planning, approved snapshots, credits, jobs, workers, providers, rendering, tools, Stripe, deployment, or broad service-role execution.

## Status Values

- `implemented`: route/service code exists for the limited Prompt 4 scope.
- `mock_only`: local/mock behavior exists and must not be treated as production.
- `backend_required`: production behavior requires backend Supabase/storage credentials and validation.
- `blocked`: intentionally unavailable.
- `future`: planned but not implemented.

## Route Guardrails

- Mutation routes must require auth and idempotency except local-only byte upload helpers.
- Production signed upload/download routes must be backend-only and temporary.
- Canonical records must store bucket/path, not signed URL values.
- Project access must resolve through workspace membership.
- Source media finalization must not start probe, transcript, analysis, planning, snapshots, credits, jobs, workers, providers, rendering, tools, or billing.
- Backend-required routes must fail closed when service-role/storage runtime is unavailable.
