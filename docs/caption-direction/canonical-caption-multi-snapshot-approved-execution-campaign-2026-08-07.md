# Canonical Caption Multi-Snapshot Approved Execution Campaign

Milestone: `POST-CAP-20-CANONICAL-APPROVED-EXECUTION-CAMPAIGN-V1`

Date: 2026-08-07

## Outcome

Caption now has a versioned, create-only backend record for combining execution
coverage from multiple exact approved snapshots. The record is intentionally
preterminal. It proves that approved Caption jobs executed through the
canonical one-job adapter; it does not replace artifact-byte inspection,
authenticated owner evidence, complete-time visual review, independent final
QA, or private-review acceptance.

The source-only internal campaign currently proves 21 of the 41 declared
Caption job types across three distinct approved snapshots and execution
packages. It adds approved execution evidence for:

- `resolve_multi_track_caption_scene`;
- `resolve_spatial_typography`;
- `resolve_hero_typography`;
- `resolve_persistent_topic_typography`.

Twenty catalog job types remain outside this campaign. The implementation does
not fabricate one edit containing every feature. Each advanced scenario passes
through its own preferences, source-analysis authority, immutable plan,
estimate, approval, snapshot, execution package, PictureLock/finish binding,
job closure, persistence, QA claim reread, and reconciliation.

## Canonical boundaries

`canonical-caption-approved-execution-campaign-v1` rereads the existing
`canonical-caption-approved-execution-coverage-v1` records through the
coverage repository. It requires:

- at least two unique execution-package refs;
- one distinct approved snapshot and execution package per run;
- a single owner/workspace/project scope;
- the exact Caption capability-manifest ref;
- deterministic catalog-order union and complement lists;
- create-only campaign persistence, identical replay, and exact reread;
- all nested coverage to remain preterminal.

Duplicate runs, a single-run campaign, crossed package lineage, forged terminal
qualification, browser-local completion, and any positive runtime/provider/
asset/final-QA/billing/public/production authority fail closed.

## Sequential support correction

The campaign exposed two real integration gaps and the implementation corrected
the owners rather than weakening validators:

1. Late spatial jobs did not receive the typed final-frame Visual Intelligence
   support payload after PictureLock. The canonical Caption execution service
   now constructs that payload from exact confirmed-frame, scene, occupancy,
   PictureLock, finish-readiness, source-manifest, and approved-snapshot
   lineage.
2. A Visual Intelligence owner resume lost the already-authenticated canonical
   transcript payload. Visual Intelligence now persists the authenticated owner
   projection, while the canonical Caption execution owner rereads that exact
   record together with the transcript and resumes the call. No peer dispatcher
   or second execution owner was introduced.

The structural Visual Intelligence fixture was updated to satisfy the current
canonical deterministic-tool lineage. It remains explicitly
`structural_fixture_not_private_qualification`: it performs no live provider or
media execution and cannot be counted as Visual Intelligence qualification.
