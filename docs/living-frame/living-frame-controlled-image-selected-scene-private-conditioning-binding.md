# Living Frame selected-scene private conditioning binding

Status date: 2026-07-29

Status:
`private_conditioning_brief_leases_created_prompt_packet_merge_pending`

`living-frame-controlled-image-selected-scene-private-conditioning-binding-v1`
closes the source-fidelity gap between an approved Living Frame scene and the
existing private ComfyUI prompt materializer. It proves that positive and
negative conditioning text comes from the exact selected scene, exact
generated output, validated Visual Continuity Pack, animation-aware component
direction, confirmed frame, and source-truth policy. It does not use a generic
benchmark prompt.

This is a namespaced, non-executable candidate. It does not register the
ComfyUI operation, select a production tool, dispatch work, run a GPU, persist
an asset, create actual cost, mutate the asset manifest, approve QA, render a
final canvas, charge a customer, or claim production readiness.

## Product meaning

Living Frame is not a universal 2.5D filter. The selected scene decides whether
its approved depth language is flat, shallow 2.5D, deep multiplane, or
dimensional. This binding preserves that decision in the image source:

- a cinematic-anime character scene may request clean inked silhouettes,
  separable clothing, weapon, hair, and environment layers;
- an archival scene may request a restrained archival treatment;
- a technical scene may request exact clean technical form;
- a flat editorial scene remains flat when that is the approved design; and
- every generated image remains a still source for later deterministic
  selective motion.

The image model is the illustrator. It does not become the animator,
cinematographer, SoundSync owner, StoryTiming owner, or final compositor.
Remotion retains the final canvas and deterministic motion ownership.

The private receipt now records one exact motion-preparation class rather than
reducing every non-flat scene to a generic 2.5D instruction:

| Approved depth style | Private motion-preparation class | Source-image direction |
| --- | --- | --- |
| `flat` | `flat_layer_animation` | semantic 2D masks, transforms, and reveals; no parallax or fake extrusion |
| `shallow_2_5d` | `shallow_2_5d_parallax` | minimum restrained near/subject/background separation |
| `deep_multiplane` | `deep_multiplane_parallax` | explicit far, background, subject, front, and foreground planes |
| `dimensional` | `dimensional_spatial_composition` | coherent perspective, volume, overlap, and occlusion without generated video |

Only the shallow and deep-multiplane classes are counted as 2.5D-directed.
Dimensional treatment is tracked separately rather than being mislabeled as
2.5D.

The binding revalidates the original inputs of all three upstream contracts.
It then requires exact agreement across:

Cross-scene, cross-component, cross-work-item, cross-output, cross-manifest,

## Animation-aware illustration

The conditioning brief is compiled deterministically from validated fields. A
caller cannot supply prompt text.

Every approved asset treatment receives treatment-specific preparation rather
than only passing an enum name to the image model. The compiler covers
photographic, archival, editorial cutout, vector, paper collage, technical,
cinematic realistic, cinematic anime, sumi-e ink, and graphic-novel language.
Those directions control silhouette, material, line hierarchy, separability,
detail, and documentary restraint without imitating named artists.

The positive conditioning includes:

- narrative purpose and visual verb;
- exact component role, depth, and derived direction;
- scene composition strategy and depth style;
- style-bible asset treatment, line language, palette, lighting, edge,
  texture, and detail density;
- linked character, object, and environment continuity summaries when
  applicable;
- motion language only as downstream animation-preparation guidance;
- complete silhouettes and layer boundaries;
- independently isolatable moving parts;
- foreground/background separation;
- no baked motion or effect dependency;
- exact isolated or confirmed-ratio source dimensions; and
- an explicit statement that matting, rigging, motion, camera, sound, and
  final Remotion composition remain downstream.

The negative conditioning prohibits:

- text, labels, watermark, signature, logo, and UI;
- baked motion blur, trails, smoke, dust, particles, glow, camera movement,
  or animation frames;
- fused moving parts, cropped silhouettes, or irreversible composites;
- fake transparency and opaque rectangles presented as final alpha;
- FaceID, InsightFace, or unsupported identity reconstruction;
- authentic-archive or verified-evidence claims;
- final-video-canvas claims;
- model, path, URL, command, credential, or runtime instructions; and
- the Visual Continuity Pack's exact avoidance codes.

For an isolated component, the source remains `1024 × 1024` on a uniform,
easily separable opaque field. ReeditPro's existing rembg/Sharp path owns
future alpha production and QA.

For a source or background plate, dimensions come only from the confirmed
frame-ratio extension. The current representative fixture proves an exact
`3840 × 2160` landscape plate with no `1024 × 1024` substitution. The plate is
still only a source asset; it never becomes the final canvas.

## Source-truth boundary

Every unit records whether documentary, geography, or data fact revalidation
is required. Generated output is always an illustrative source unless another
canonical evidence owner proves more.

The conditioning text must not:

- claim a verified likeness;
- claim authentic archival evidence;
- imply an unsupported action;
- fabricate exact map geometry, data, dates, documents, insignia, quotations,
  locations, or events; or
- replace deterministic map, chart, diagram, label, or documentary evidence
  owners.

Controlled reference-view expectations in the Visual Continuity Pack remain
unverified expectations. This binding cannot turn one into a persisted
reference artifact. Reference-conditioned materialization remains blocked
until the canonical artifact and alignment owners provide released evidence.

## Private delivery and real prompt-materializer integration

The serializable receipt contains only digests, counts, enums, byte lengths,
lineage, and explicit non-authority flags. It contains no subject-specific
summary, conditioning text, pack payload, reference image, model alias, path,
URL, bytes, credential, seed, caller dimension, command, or environment.

The private brief remains in a process-local weak binding behind a single-use
lease. Copying a lease object does not copy access. Consuming the real lease
once permanently removes the private value.

The animation-aware prompt-reader adapter accepts only an exact server-owned
alias packet whose two text slots contain the fixed
`server-owned-conditioning-pending` sentinel. It consumes exactly one
conditioning lease for every approved output, replaces only those two text
slots, and passes the resulting private packet to the existing selected-scene
prompt materializer. Model and image aliases remain owned by the existing
private artifact repository. The merge validates every packet unit and every
process-bound lease before consuming any lease, so a rejected later unit
cannot partially consume earlier units.

The integration smoke proves that the positive and negative slot digests in
the actual selected-scene prompt-materialization receipt exactly equal the
conditioning digests in this binding. Benchmark recipes and generic prompt
text are not used.

The adaptive-style matrix additionally proves:

- flat editorial-cutout scenes never receive 2.5D or dimensional direction;
- paper-collage scenes receive restrained shallow-2.5D preparation;
- cinematic-anime scenes receive deep-multiplane preparation;
- dimensional graphic-novel scenes receive coherent volume and perspective
  preparation without being counted as 2.5D; and
- every class remains a still-source request with downstream Remotion
  ownership.
