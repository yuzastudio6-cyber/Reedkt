# Living Frame Canonical Integration Supplement

`living-frame-canonical-integration-supplement-v1` is the source-only whole-
pipeline handoff for the owner-approved Living Frame scope. It binds the
otherwise separate source contracts into one auditable dependency map without
becoming a readiness, approval, timing, work, asset, renderer, QA, private-
review, chat-card, cost, or delivery owner.

## Bound evidence

The supplement records exact policy-object digests for the owner-scope
amendment and active Professional Skill policy projection. It also freezes the
representative source-regression digests for the 12-case active manifest,
structural evidence admission, map/archive/diagram/hybrid lineage, and chat
presentation. Contract-identity references cover postrender visual inspection,
Caption Direction, motion v3, and semantic SoundSync reconciliation.

Representative digests are evidence that the exact source regressions passed;
they are not substitutes for canonical immutable project-record rereads. Every
project-bound reference remains pending at the canonical owner boundary.

Each point names what the existing canonical owner consumes and must preserve.
No point grants this supplement authority to perform that work.

## Tools and controlled generation

The supplement records exact registry classifications for FFmpeg, FFprobe,
Remotion, rembg, Sharp, SAM2, PixiJS, D3, Satori, Viz.js, SVG.js, and ComfyUI.
It does not add or reclassify any identity. SAM2 and ComfyUI are explicitly
validated as existing non-E2E capability identities, not production
identities. The observed 50 production and 23 non-E2E identities are a source
fingerprint, not a product cap; later expansion is permitted only for a
genuinely distinct, fully released executable boundary.

ComfyUI remains one unreleased candidate host and one candidate operation. The
host owns controlnet_aux preparation, ControlNet, generic IP-Adapter plus CLIP
Vision, and PEFT/LoRA inside one supervised GPU attempt and one cost event.
Those capabilities are not separate tools or charges. AuraFace has no shared
registry identity today. It remains a future separate optional CPU-QA
candidate and is non-admissible under the current active owner scope.

Qwen is a visual-evidence model role, not a deterministic tool. Kimi is the
primary Head QA reasoner and GPT-5.6 Terra is the classified fallback. None of
the models may replace canonical private review.

## Authority boundary

`canonicalConsumptionPending` is `true`. Shared registry, planner, and UI
owners are unchanged. Runtime, provider, dispatch, artifact, cost, QA approval,
private review, billing, public delivery, and production authorities are all
false. The supplement contains no raw chat, transcript, captions, audio,
media bytes, paths, URLs, prompts, credentials, commands, or environment data.
