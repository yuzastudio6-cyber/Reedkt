# Canonical source-led advanced Caption planning — 2026-08-07

Status: `source_complete_private_internal_evidence_pending`

## Outcome

The normal canonical source-led planning owner is no longer hard-coded to the
17 baseline Caption assignments. It still emits exactly those 17 assignments
for the existing clean source fixture, but it can now select applicable
advanced scene and boundary work from the already-compiled professional editing
directive.

Selection remains owned by the canonical plan. The Caption owner consumes only:

- the exact professional-skill composition trace;
- the reread canonical source-analysis authority;
- confirmed output-frame and MasterTiming lineage;
- typed `captionStyle`, `editStyle`, `pacingStyle`, and `soundStyle` values; and
- high-confidence structured `mappedPresetIds` with no unresolved clarifying
  questions.

Raw custom-directive strings, `rawUserRequest`, and `interpretedMeaning` are not
read as planning instructions. Unknown, low-confidence, medium-confidence, and
unresolved mappings cannot activate advanced Caption work.

## Reachable normal-owner profiles

The focused source regression proves 18 representative profiles through the
real source-led owner and downstream canonical work projection:

- stable baseline Caption lifecycle;
- sentence-block spatial composition;
- explicit spatial-composition and camera-coordination mini-skills;
- subject-occluded typography;
- object-anchored typography;
- environmental typography;
- multi-track speaker typography;
- hero typography;
- persistent-topic typography;
- B-roll, Living Frame, map, chart, diagram, and transition Caption-to-Visual
  boundary planning;
- B-roll co-composition shorthand using the existing Caption mini-skill; and
- Caption sound/timing coordination.

The owner activates the existing `caption_design` mini-skills and derives only
the corresponding assignment intents. It does not fabricate one all-feature
edit. Multiple unscoped tracking treatments or multiple cross-system receivers
fail closed and require scene-scoped clarification.

Incoming support jobs are deliberately absent from the initial plan. The owner
may create boundary requirements, but the later support job still requires its
exact HQ-mediated typed support request and immutable request/result lineage.
Caption never dispatches B-roll, Living Frame, Transitions, SoundSync, Track
All, or another peer directly.

`npm run smoke:canonical-caption-source-led-professional-planning-owner`
passes 181 assertions. Each accepted advanced profile is also projected into
the canonical downstream Caption work graph and checked for exact assignment
count and ordering. The regression additionally proves:

- simple Caption planning remains 17 assignments;

- no-captions restraint still creates no Caption work or estimate;
- no-captions restraint ignores superseded advanced mappings, including a
  stale conflicting receiver pair;

## Remaining evidence boundary

This milestone fixes a real normal-pipeline reachability gap. It is source
evidence, not terminal qualification. No new provider, model, media, render, or
visual-review runtime was used. Representative approved advanced-caption edits
must still execute their exact work graphs, obtain authenticated shared-owner
evidence, render, pass deterministic QA, receive qualified complete-time visual
review, and pass independent final QA before their jobs enter the terminal
multi-run qualification catalog.
