## Outcome

The exact local Linux/AMD64 ComfyUI candidate image now has a bounded,
image-derived SPDX 2.3 package inventory. The evidence is generated by running
fixed package-manager queries inside the immutable image with:

- `--network none`;
- a read-only root filesystem;
- explicit UID/GID `65532:65532`; and
- the fixed Linux/AMD64 platform.

The server reads the process-bound observation twice, requires an identical
inventory, verifies the exact image digest and source labels, checks all 35
locked wheel identities, and projects a deterministic SPDX document. The
document is returned only through a process-bound, single-use byte lease. The
serializable evidence contains only counts, digests, fixed revisions, policy
findings, and closed authority flags.

The current exact observation is:

| Debian packages | 590 |
| Python distributions | 168 |
| Locked ComfyUI wheel distributions | 35 |
| Inherited Python distributions | 133 |
| Pinned source archives | 3 |
| Total SPDX packages | 761 |

The deterministic document is 253,699 bytes with SHA-256:

`dd7fd3bf99acf78a25bc61b0fb97b10e309b68fdb5c70c8581db3073c270bf5d`

It must change if the image inventory changes.

## Findings

The inventory exposed two release-policy failures that the wheel/source lock
alone could not prove:

1. The image has no default non-root user. The controlled observation succeeds
   only because the container runner explicitly applies UID/GID
   `65532:65532`.
2. The shared inherited Python environment includes one out-of-scope direct
   VCS distribution, normalized as `sam-2`, at revision
   `2b90b9f5ceec907a1c18123530e92e794ad901a4`.

The SPDX projection deliberately removes the original installation paths and
repository URL. It preserves the normalized package identity and revision so
security, license, and image-scope reviewers can make a disposition.

These findings do not prove that the package is exploitable or unusable. They
prove that the current image cannot pass release policy merely because its 35
operation-specific wheels are locked.

## Evidence Boundary

This contract proves:

- exact local image identity;
- exact base, wheel-manifest, ComfyUI, IP-Adapter, and ControlNet auxiliary
  labels;
- stable Debian and Python package-manager inventories;
- the exact locked-wheel set inside the installed environment;
- the three pinned source archive revisions;
- a sanitized deterministic SPDX 2.3 package document; and
- single-use document delivery.

It does not prove:

- canonical image-repository admission;
- independent SPDX schema validation;
- vulnerability scan or vulnerability disposition;
- image signature;
- SLSA or other provenance attestation;
- package or model commercial-use approval;
- L4 compatibility;
- canonical operation registration;
- private dispatch;
- production readiness; or
- public/customer use.

The failed generic Docker SBOM attempt is not evidence. It exhausted the local
temporary volume while exporting the 31 GB image and returned no complete
document. The bounded in-container inventory avoids copying image layers and
fails closed if the exact package set, source binding, image identity, runtime
confinement, or repeated observation changes.

## Required Release Work

Before the image can be admitted:

1. Decide whether the production worker image must set a default non-root user
   or whether the released canonical runtime can provide a separately attested
   mandatory user override.
2. Review or remove the inherited out-of-scope VCS distribution.
3. Review the complete inherited Debian and Python dependency surface.
4. Validate the generated SPDX document independently.
5. Run an approved vulnerability scanner and record dispositions.
6. Build, scan, sign, and attest the exact release image.
7. Re-run the same inventory against that release digest.
8. Complete the L4, model-artifact, operation, cost, QA, and private-review
   gates.

No tool-registry, operation, dispatch, billing, approval, or production
authority is created by this evidence.
