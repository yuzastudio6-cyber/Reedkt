# Local Supabase Environment Manual Setup

Prompt 20C documents the manual local environment setup required before the first executable local RLS smoke test. It does not run SQL, start Supabase, reset Supabase, apply migrations, touch staging/remote/production Supabase, deploy, create records, or unlock beta.

## Current Blockers

- `/usr/local/bin/supabase` is `x86_64` and fails on this arm64 host with error `-86`.
- `psql` is not on PATH.
- no verified local Supabase database URL exists.
- no executable local-only SQL candidate exists under `database/test-sql/local/`.

Resolved by Prompt 20A:

- `supabase/config.toml` exists and is local-only.
- Docker is reachable on this host.
- no `.supabase` remote project-ref indicator was detected.
- no risky Supabase/database/provider/payment env var names were detected by local preflight.

## Official Guidance References

Use current official Supabase docs as the source of truth for manual setup:

- Local Supabase development requires the CLI plus a Docker-compatible container runtime: `https://supabase.com/docs/guides/local-development`
- The CLI guide documents `supabase init` for local project setup and `supabase start` for launching local services: `https://supabase.com/docs/guides/local-development/cli/getting-started`
- The CLI guide states that `npx supabase` requires Node.js 20 or later and that global `npm install -g supabase` is not supported.
- The CLI config guide documents that `supabase/config.toml` is generated by `supabase init`: `https://supabase.com/docs/guides/local-development/cli/config`

## Supabase CLI Setup Options

Allowed manual repair options outside repo commits:

- Homebrew arm64 CLI path, preferably `/opt/homebrew/bin/supabase` on Apple Silicon.
- Standalone arm64 Supabase CLI binary placed outside the repository.
- `npx supabase` only after confirming Node.js 20 or later and local-only command intent.
- Dev dependency install only as a future reviewed repo decision, not in Prompt 20C.
- Docker-compatible CLI route only if a later prompt explicitly approves the local-only command shape.

Unsupported or blocked:

- global `npm install -g supabase`.
- committing downloaded CLI binaries.
- `supabase link`.
- remote `supabase db push`, remote migration, or remote SQL commands.

Manual architecture checks:

```sh
uname -m
which supabase
file "$(which supabase)"
supabase --version
```

Expected Prompt 20B state on this host:

- `uname -m` reports `arm64`.
- `file "$(which supabase)"` reports an arm64-compatible binary or `npx supabase` runs through an arm64 Node path.
- `supabase --version` exits successfully.

## psql Setup Options

`psql` is required by the guarded local RLS runner unless a future prompt approves another local-only SQL executor.

Allowed manual options outside repo commits:

- Postgres.app command-line tools.
- Homebrew `postgresql`.
- Homebrew `libpq` with PATH configured outside the repo.
- a future reviewed Docker-based `psql` route that connects only to the local Supabase DB URL.

Verify with:

```sh
which psql
psql --version
```

Do not use `psql` against staging, remote, or production databases.

## Docker Requirements

Supabase local development uses Docker-compatible containers. Docker is reachable after Prompt 20A, but it is not enough on its own because the Supabase CLI and `psql` still block local SQL.

Verify Docker manually with:

```sh
which docker
docker --version
docker info --format '{{.ServerVersion}}'
```

Do not use a remote Docker host for local Supabase validation.

## Local Config Verification

Before Prompt 20B, verify `supabase/config.toml` remains local-only:

- `project_id` remains `reeditpro-local`.
- no `[remotes.*]` block exists.
- no `.supabase.co` URL appears.
- no env secret reference appears.
- ports are local-only development ports.
- no staging or production project ref appears.

Do not run `supabase link` in this repo.

## Env And Remote-Link Verification

Run:

```sh
npm run --silent supabase:local:preflight
```

The preflight must show:

- `remoteRiskDetected: false`
- no `.supabase/project-ref`
- no `.supabase/.temp/project-ref`
- no risky Supabase/database/provider/payment env var names
- no critical findings

The script reports env var names only and must not print values.

## Local DB URL Verification

Prompt 20C does not run `supabase start` or `supabase status`.

For Prompt 20B or a setup verification prompt, the local DB URL may be accepted only when:

- the Supabase CLI is compatible and executable;
- Docker/local runtime is verified;
- no remote risk is detected;
- the URL host is `localhost`, `127.0.0.1`, or `::1`;
- no staging, remote, or production URL is used;
- the value is redacted in evidence.

## Safe Commands

Prompt 20C safe commands:

```sh
npm run --silent supabase:local:preflight
npm run supabase:rls:list-tests
npm run supabase:rls:local:dry-run
```

Prompt 20C should not run SQL.

## Forbidden Commands

Do not run:

- `supabase link`
- remote `supabase db push`
- remote migration commands
- local or remote SQL execution
- `supabase start` in Prompt 20C unless a later instruction explicitly approves it
- `supabase db reset`
- `psql` against any database
- provider, tool, worker, render, media, storage, credit, Stripe, telemetry, deploy, or beta-unlock commands
