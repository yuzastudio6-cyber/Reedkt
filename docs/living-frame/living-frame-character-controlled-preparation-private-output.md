# Living Frame character controlled-preparation private output

## Purpose

`living-frame-character-controlled-preparation-private-output-v1` defines the
feature-owned, non-authoritative boundary that may observe one exact opaque PNG
returned by the future canonical ComfyUI v2 character-preparation route.

The contract exists so Living Frame can validate the returned bytes and carry
them to the existing private persistence, QA, route-recompilation, manifest,
review, and Remotion stages without:

- creating a second ComfyUI runtime or operation;
- treating a structural result envelope as worker-completion proof;
- accepting caller paths, URLs, prompts, model choices, dimensions, commands,
  credentials, environment, or arbitrary output bytes;
- claiming artifact, QA, cost, route, render, billing, public-delivery, or
  production authority; or
- allowing ComfyUI to own the final canvas.

The current smoke uses a controlled source fixture. It is contract evidence,
not proof that the canonical v2 compiler exists or that an L4 worker executed.

## Upstream binding

The observation binds all of the following before reading output bytes:

- the exact approved snapshot ID and digest;
- the exact approved work-graph digest;
- the current MasterTiming digest;
- the confirmed output-frame expectation digest;
- the exact character controlled-preparation unit and digest;
- the exact private prompt unit and digest;
- the exact graph-topology digest;
- the selected scene and component;
- the exact approved work item and work key;
- the planned asset-manifest entry;
- the expected output key;
- the future canonical request and result candidate digests;
- the fixed runtime identity, confinement requirement, model-mount reread,
  resource/cost, and structural worker-receipt lineage digests; and
- one output candidate ID, content type, dimensions, byte length, encoded
  content digest, and decoded RGBA digest.

The worker-receipt, runtime, mount, and resource/cost digests are structural
lineage fields only in the controlled fixture. The receipt explicitly records
that canonical worker completion was not inferred, no GPU attempt was created,
and no actual cost evidence was verified.

## Exact masked-plate boundary

The first admitted observation scope is deliberately narrow:

```text
reconstruct_exposed_source_plate
→ confirmed_full_frame_ratio
→ opaque_masked_plate_requires_hidden_plate_continuity_fact_and_destination_qa
```

The observed plate must retain the corrected pinned ComfyUI contract:

- gray8 mask PNG;
- `LoadImageMask`;
- channel `red`;
- output index `0`;
- white/one means inpaint;
- `VAEEncodeForInpaint`;
- `grow_mask_by = 6`;
- sampler `denoise = 0.55`;
- no plain-`LoadImage` mask substitution;
- no `EmptyLatentImage` substitution; and
- no arbitrary node or input-slot expansion.

The source/background plate uses the exact confirmed 1920×1080 frame in the
current fixture. An isolated component remains a separately bounded 1024×1024
unit and is not interchangeable with the plate.

## Private byte handling

The future canonical result envelope is byte-free. A server-created,
process-bound, single-use reader supplies one exact PNG packet. The observer:

1. consumes the reader once;
2. revalidates every packet lineage field;
3. rehashes the encoded PNG;
4. decodes the exact expected dimensions;
5. verifies the decoded RGBA digest;
6. recomputes the alpha measurement from decoded pixels;
7. emits a byte-free observation receipt; and
8. places the verified bytes behind one process-bound, single-use private
   output lease.

The lease does not persist or reconcile the artifact. It only permits the next
approved private stage to consume the already verified bytes once.

This boundary is character-preparation preverification, not a replacement for
`living-frame-controlled-image-selected-scene-private-output-observation-v1`.
That existing selected-scene observer currently accepts only its v1 operation
receipt, whose graph excludes masked inpaint. The future canonical v2
integration must add a narrow adapter into that existing observer lane. The
adapter may reverify the same bytes; it must not create another persistence,
QA, manifest, or private-review owner.

## Fail-closed behavior

The contract rejects:

- reader or output-lease replay;
- cross-scene, cross-component, cross-work-item, or cross-output substitution;
- isolated-component substitution for a masked full-frame plate;
- square substitution for the confirmed full frame;
- graph-topology or prompt-unit substitution;
- encoded-byte or decoded-pixel digest mismatch;
- dimensions outside the confirmed frame;
- non-PNG, transparent, or malformed output;
- unsafe URLs or additional caller-controlled fields;
- forged worker-completion, artifact, QA, route, render, or production
  authority; and
- receipt leakage of bytes, paths, URLs, prompts, model choices, credentials,
  commands, environment, price, credits, service fees, reservations, wallet,
  or ledger data.

## Required downstream work

An accepted observation remains an intermediate asset candidate. It still
requires:

1. a released canonical ComfyUI v2 request/result compiler;
2. a v2 adapter into the existing selected-scene private-output observation;
3. a signed, scanned, non-root L4 image;
4. the fixed supervised Python entrypoint and exact five-model,
   11,700,367,157-byte atomic read-only mount—base checkpoint, ControlNet,
   LoRA, generic IP-Adapter, and CLIP Vision—with before/after verification;
5. real L4 inference and canonical resource/cost evidence;
6. create-only tenant-private persistence and exact reread;
7. hidden-plate continuity, face-clearance, documentary fact, and destination
   composite QA;
8. Living Frame character-route recompilation after QA;
9. canonical asset-manifest reconciliation;
10. private review; and
11. final Remotion composition.

The canonical owners of approval, MasterTiming, work graph, asset manifest,
cost, QA, private review, and final rendering remain unchanged.
