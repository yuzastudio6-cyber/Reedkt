# Generated SFX Library Growth

## Purpose

RP-SFX-09 adds mock-only generated SFX library growth. ReeditPro can begin with no internal SFX library, generate project-only sounds when needed, QA them, record usage, review provenance/privacy risk, and only then consider safe reusable sounds as future library candidates.

This does not call Mirelo, call MMAudio, process audio, connect to Supabase, run migrations, upload files, render media, approve real library assets, or build UI.

## No Library At Launch

No approved SFX library at launch is acceptable.

```text
search internal library
-> no match
-> generate project SFX later
-> QA it
-> use project-only
-> evaluate candidate only if reusable and safe
```

As the mock data grows, usage and QA signals can teach future ranking without overriding privacy, licensing, or user intent.

## Project-Only First

Generated SFX starts as `project_generated`. If QA passes or warns, RP-SFX-09 can mark project use as `approved_for_project`. If QA fails, removal is recommended, or policy is violated, reuse becomes `blocked_from_reuse`.

Project-only storage in this milestone is metadata only. No audio file is copied, uploaded, rendered, or processed.

## Library Search

Library search records store:

- target layer
- use case
- desired volume profile
- desired duration
- tone words
- search tags
- match strength
- fallback reason

Empty-library scenarios return `none` and fall back to generated project SFX. Mature-library scenarios can return `strong` or `exact` with a mock approved library asset ID.

## Provenance Review

Provenance review models:

- provider and model
- license provenance ID
- commercial use
- ads use
- client work use
- cross-user reuse
- attribution
- terms review requirement
- risk level

Missing provenance or unclear provider terms sets `termsReviewRequired = true`. Cross-user reuse is never assumed unless the mock scenario explicitly allows it.

## Privacy And Reuse Policy

Reuse is blocked or limited when SFX is based on:

- private project context
- user voice or identity
- client-specific work
- branded sonic identity
- restricted reference material
- failed QA
- missing provenance

Workspace-only is used for client or brand-specific sounds that may be useful inside one workspace but not across ReeditPro.

## Candidate Promotion

Candidates require:

- QA pass or safe warning
- quality score at least `85`
- general-purpose use
- useful target layer/use case
- timing metadata
- clean trim
- mix metadata
- tags
- no private or reference-copy risk

`approved_internal_library` is only allowed in explicit mock approval scenarios where QA is strong and provenance permits cross-user reuse.

## Usage Records And Learning

Usage records capture preview/export placement, hit time, volume profile, QA result, and user kept/removed state.

Usage learning stores:

- kept or removed signal
- preview/export use
- QA pass state
- regeneration request
- replacement request
- tag improvements

Positive signals help future ranking. Negative signals teach the library to avoid similar cues.

## Examples

Lake Como lifestyle:

- soft premium transition whoosh can become a candidate but may require terms review
- title hit can become a candidate if general-purpose
- ambient bridge stays project-only when it is scene-specific
- fake water or footsteps should not be generated by default

Stroke Motion:

- subtle draw textures can become candidates when general-purpose and safe under voice

Graphic Design:

- clean card reveal pops can become candidates if not cheap, cartoonish, or brand-specific

Real Motion:

- generic object settle can become a candidate, but room-specific object sounds usually stay project-only

## Mock-Only Boundary

RP-SFX-09 creates mock library-growth metadata only. It does not promote real assets, write storage, connect to a database, process audio, call providers, or expose any provider/license secret.

## RP-SFX-10 Chat UI Handoff

RP-SFX-10 displays the project-only and library-candidate decisions in chat. It shows reuse status, candidate reason, quality score, privacy/provenance flags, tags, recommended use cases, avoid use cases, and the reminder that generated SFX starts project-only.

## RP-SFX-11 Worker Handoff

RP-SFX-11 connects library-growth metadata to a mock worker skeleton. After approval and credit gates pass, the worker can simulate internal-library matches, mock provider output, QA, usage records, provenance review, reuse policy, and candidate decisions in one deterministic run.

The worker still does not promote real assets or assume cross-user reuse. Library approval remains mock-only and provenance-gated.

The next milestone after RP-SFX-11 is future real provider integration work, not automatic library promotion.
